### A. 阻断级（不补就没法给别人用）

#### A1. 导出包里读不到 `settings/*.json` —— 五个配置文件全走 `System.IO` + `res://`
- **缺什么**：导出包里 `ProjectSettings.GlobalizePath("res://settings/xxx.json")` 的可用性。
- **在哪**（全部是"读 `user://` 优先 → 退 `res://settings/`"的同一个模式，且都用 `System.IO.File.ReadAllText`）：
  | 配置文件 | 代码位置 |
  |---|---|
  | `agent.json`（后端/可执行文件/工作目录） | `script/Agent/AgentBridge.cs:74-79`（`ProjectSettings.GlobalizePath` + `File.Exists`/`ReadAllText`） |
  | `behavior.json`（自主行为全部旋钮） | `script/State/StateMachine.cs:862-865` |
  | `pet.json`（缩放） | `script/UX/CharAnim.cs:42-45` |
  | `panel.json`（命令栏隐藏指令） | `script/UX/ChatBox.cs:305-308` |
  | `tts.json`（语音输出） | `script/Audio/Tts.cs:56-59` |
- **依据**：Godot 维护者 Calinou 明确说过「In an exported project, `res://` only finds files within the PCK (or embedded PCK), not in the same folder as the exported binary. Use `OS.get_executable_path.path_join(...)`」（godotengine/godot#76817 评论，2023-05-07）。同一 issue 里报错方的 `globalize_path("res://…")` 返回空串。→ 用 `System.IO` 去读 `res://` 下的文件，在导出包里**不可依赖**。
- **后果（静默，不崩）**：五个配置全部走代码内默认值 —— 没有 Agent（本地桌宠模式）、默认节律、默认缩放、默认面板、默认语音。用户拿到程序会以为「它不会说话 / 它坏了」。
- **怎么补**（建议两条都做）：
  1. **随包把 `settings/` 复制到 exe 同级**（现在 `export_presets.cfg:26` `embed_pck=false`）——最小改动，且给了用户一个"就在眼前"的编辑位置；
  2. **改读法**：仿 `script/Util/LoadUtil.cs:144-149` 已有的分支写法（`OS.HasFeature("editor") ? GlobalizePath("res://…") : Path.Combine(OS.GetExecutablePath().GetBaseDir(), …)`），或改用 `Godot.FileAccess`（能读 PCK 内文件；`SoulTable.cs:65-69` 就是这么读模板的，**模板在 PCK 里能读到**）。
- ⚠ **未验证**：这两条都必须在真实导出包上实测（§4 验收清单第 5-7 步）。顺带一个边界：`settings/soul_template.md` 是 `.md`（不是导入型资源），会不会被 `export_filter="all_resources"` 收进 pck **未验证**；若没进去，首启生成的 `soul.md` 会退化成一行桩文案 `# 我是谁\n（人格未配置）`（`SoulTable.cs:20,63-71`），用户第一次看到的人格就是空的。

#### A2. `mods/` 与 `config/` 必须随包为独立目录 —— 否则桌宠是空壳
- **缺什么**：打包步骤里"复制 mods / config"这一环（现在完全不存在）。
- **依据**：
  - `script/Util/LoadUtil.cs:143-149`：**非编辑器构建**下 `ModPath`/`ConfigPath` = `Path.Combine(OS.GetExecutablePath().GetBaseDir(), "mods"|"config")`；
  - `script/Loader/ModLoader.cs:16-21`：三个来源（`LoadUtil.ModPath` / exe 上级目录（Steam）/ 创意工坊）；
  - `script/Loader/AnimLoader.cs:15-17`、`DialogueLoader.cs:16-17`：目录不存在直接 `return`（**不报错**）→ 没有动画、没有指令、没有入场招呼；
  - `mods/.gdignore` 存在（`find` 实测）→ Godot 资源系统眼里 `mods/` 不存在（对运行无害，因为按绝对路径读；但也别指望它被打进 pck）。
- **怎么补**：打包脚本里 `cp -r mods config settings "<包目录>/"`；验收时确认「角色会动、右键菜单里有指令」（§4 第 6/8 步）。

#### A3. `settings/agent.json` 里是作者机器的绝对路径

## 2. cwd 干净化核查（ACP 子进程的工作目录）

**问题**：桌宠把 `hermes acp` 拉起来当子进程；如果它的工作目录（cwd）是含 `AGENTS.md` 的项目目录，Agent 会按 cwd 把那份工程契约读进 system prompt（`script/Agent/README.md:53` 已警告过）。

### 2.1 现状（证据链）

**桌宠侧**：
1. `settings/agent.json:5` → `"workingDirectory": ""`（留空），且文件注释写明「留空则用 `user://`（必须干净，勿指向含 AGENTS.md 的项目目录）」。
2. `script/Agent/AgentBridge.cs:144-146`：启动后端前，若 `WorkingDirectory` 为空 → 填 `ProjectSettings.GlobalizePath("user://")`。**这一行在启动路径上一定会执行**（`Start()` 是唯一拉起后端的地方）。
3. `script/Agent/AcpClient.cs:51-52`：兜底 —— 万一还为空，取 `"."`；`:57` 把它设成 `ProcessStartInfo.WorkingDirectory`（子进程的真实 cwd）。
4. `AcpClient.cs:85 / 105-136`：这个 cwd 同时作为 `session/new` 与 `session/resume` 的 `cwd` 参数发给 Agent。

**实测**：`%APPDATA%\Godot\app_userdata\desktop\`（`user://`）目录内容里**没有** `AGENTS.md` / `AGENTS.override.md` / `agents.md` / `.hermes.md` / `HERMES.md` / `CLAUDE.md` / `.cursorrules`，也**没有 `.git`**（`ls -la`/`find` 实测，2026-09-16 14:38）。它只有：`agent_session.json`、`context.md`、`soul/`、`logs/`、`shader_cache/`、`objectdb_snapshots/`、几个探针截图 png、日期目录 `09-06…09-16/`。
→ **结论：cwd 干净，工程契约不会被注入。** 而且 `context.md` 之类的文件名**不在** Hermes 的项目上下文候选名单里，不会被自动注入。

**Hermes 侧**（`.py` 源码，`C:\Users\sench\AppData\Local\hermes\hermes-agent\`）：
5. ACP 客户端传来的 cwd 被用作会话 cwd：`acp_adapter/server.py:588-590`（`new_session(cwd)` → `session_manager.create_session(cwd=cwd)`）、`acp_adapter/server.py:738-740`（每轮把 `cwd=state.cwd` 写进会话上下文）。
6. 会话上下文里的 cwd 会成为「读哪些项目上下文文件」的基准：`agent/system_prompt.py:621-624` → `agent/runtime_cwd.py:69-94`（会话覆写 > `TERMINAL_CWD` > 启动目录）→ `agent/prompt_builder.py:1643-1662`。
7. 候选名单与规则（`agent/prompt_builder.py`）：`_CONTEXT_FILE_CANDIDATES`（`:1566-1571`）= `.hermes.md/HERMES.md` → `AGENTS.override.md/AGENTS.md/agents.md` → `CLAUDE.md` → `.cursorrules`（**只加载优先级最高的那一类**）；`_agents_md_directory_chain`（`:1512-1519`）= **git 根 → cwd 的目录链，没有 git 根时只查 cwd 本身**；空文件不加载（`:1574-1578`）。
8. 本机 hermes 配置 `config.yaml:63-65` 有 `terminal: cwd: .` —— 但 ACP 会话有覆写（第 5 点），且即使退到它，`"."` 解析出来仍是子进程 cwd，也就是 `user://`。

### 2.2 结论

- 当前实际 cwd = `C:\Users\<用户>\AppData\Roaming\Godot\app_userdata\desktop\`（`user://`）。
- 该目录里没有 Hermes 认识的任何项目上下文文件，也没有 git 根 → 目录链只查它自己 → **什么都不加载**。
- 即使 `workingDirectory` 被留空、被写成相对路径、或 `Start()` 被别处调用，都仍然落到 `user://`（`AgentBridge.cs:144-146` 是收口点）。
- **副作用（需要知道）**：Agent 的终端类工具在桌宠会话里是**以 `user://` 为工作目录**运行的（`acp_adapter/server.py:731-740` 的注释说明 cwd 会同时决定 system prompt 里报告的工作目录与工具根目录）。这是有意为之，但意味着 Agent 若执行相对路径写入，会写进用户数据目录。**未验证**：Agent 实际执行命令时的 cwd 行为（没在运行时抓过）。

### 2.3 残余风险

1. **开发/构建期**：把 `agent.json` 的 `workingDirectory` 手动指向仓库根（含 `AGENTS.md`，且是 git 根）→ 目录链 = 仓库根 → `AGENTS.md` 全文进 system prompt。`settings/agent.json` 的注释已警告，但**没有代码层面的拦截**（没有"cwd 里有 AGENTS.md 就拒绝/告警"这类校验）。
   → 建议：`Start()` 里加一条启动自检 —— 若 cwd 下存在 `AGENTS.md`/`.hermes.md`/`CLAUDE.md`/`.cursorrules` 之一，打印 `GD.PrintErr` 告警并记事件池（几行代码，值得）。
2. **用户侧**：`user://` 目录是用户自己的目录，如果用户**自己**往里放 `AGENTS.md` 之类的文件，那些内容会被 Agent 读到（这是 Hermes 的正常行为，不是本项目缺陷）——上手文档里提醒一句即可。
3. **`user://` 是共享目录**（按项目名 `desktop`）：别的 Godot 项目若同名会往同一目录写文件（`document/隐私与权限模型.md` §1.1 已警告）。若那个项目也往里面放 `AGENTS.md`…这属于极端情况，但它是"改名 + 迁移"（A5）之外的另一个理由去给项目一个唯一名。
