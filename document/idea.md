## 0. 总纲：这个桌宠到底是什么

**一句话**：一个**有独立人格、能感知环境、主动关心主人**的桌宠，其大脑由本地 Agent（Hermes/Ollama）驱动，身体由 Godot 呈现。

**核心职责**（展开见 §7.1）：**了解主人的各项状态，并予以帮助和陪伴。**

**人格提示词（SOUL）**：不是核心——只是一份 **prompt 资产**：Agent 读一次、**内化**进自己的人设（LLM 不会「读文件学习」——所以**程序侧不做注入**、人格也不落程序），之后按它演、跨会话不漂移。人格骨架（我是谁 / 性格 / 说话风格 / 原则 / 思维范式 / 情绪表达）与内化方式见材料本体 `dist/AIPet-SOUL.md`；它不该混进数值（§2）与记忆/画像（§3）——那两样是独立的数据。

**设计红线**：
1. **不打扰** —— 全屏/开会/专注时闭嘴；主动行为有频率预算。频繁打扰是桌宠三宗罪之首。
2. **不油腻** —— 卖萌有分寸；肉麻一次是萌，天天是负担。

**架构分层**（与 AIPet-Agent.md 一致）：
```
灵魂层(人格) ──► 能力层(Agent脑) ──► 身体层(状态机) ──► 表现(动画/语音/气泡)
     ▲                  ▲
  记忆/画像          环境感知
```

## 2. 数值系统

### 2.1 设计目标
数值是**状态表示**，不是成长属性。

### 2.2 沿用格式
- 格式：**JSON**（沿用原方案，机器读写为主）
- 位置：`user://state/stats.json`

### 2.3 基础字段（可由mod新增）

`mood` 情绪：由LLM判断用户情绪，属stats.json文件。
（暂时就这一个，想到再补充）

> 精力、亲密度、饱食度、等级等属于mod扩展范围

### 2.5 边界
- 数值**不是人格**：改数值不该改变桌宠的说话方式

### 2.6 生活节律（2026-09-22 主人细化）
桌宠有作息：
1. 当桌宠 **12 小时没睡觉**时（键鼠活跃）→ 容易**犯困**
2. 键鼠**空闲 2 小时** → **循环播放睡觉动画**
3. 键鼠**重新活跃** → **打断**睡觉
4. 键鼠**活跃间隔超过 8 小时** → 判定「**睡过了**」
5. **深夜不犯困、不劝睡**，但有特殊语句（如「主人是夜猫子呢~」）

## 3. 记忆与画像

### 3.1 设计目标
记忆和用户画像**独立于灵魂**，因为它们的**生命周期完全不同**：
- 灵魂：几乎不变（人格）
- 画像：缓慢演化（用户是谁）
- 记忆：持续累积（发生过什么）

### 3.2 文件拆分
| 文件 | 内容 | 更新频率 | 谁写 |
|---|---|---|---|
| 人格（**不落程序**） | 人格 / 思维范式 → **内化进 Agent 的人设**（交付材料 `dist/AIPet-SOUL.md` 读一次即内化） | 极少 | 用户与 Agent（自主注入） |
| `soul/profile.md` | **用户画像**：主人的喜好、习惯、长期目标、知识面、作息 | 缓慢 | Agent 提炼 |
| `soul/memory.jsonl` | **记忆流水**：事件、对话要点、承诺（一行一条 JSON） | 持续 | Agent 追加 |
| `state/stats.json` | 数值状态（`mood` = 主人情绪读数） | 高频 | 程序（值由 Agent 经 set_mood 写入） |

### 3.3 用户画像要点（供参考）
- **稳定事实**：称呼、时区、职业、偏好
- **长期目标**：主人想做什么（桌宠要记住并适时关心）
- **知识面**：主人懂什么、不懂什么（决定解释深浅）
- **习惯模式**：作息、工作节奏、情绪触发点（如「周一早上烦躁」）
- 隐私边界：画像敏感数据脱敏

### 3.4 记忆管理机制
- **写入**：Agent 判断「值得记」才写
- **检索**：按什么召回？（关键词 / 时间 / 语义向量？）
- **压缩**：超量后怎么提炼？（把流水蒸馏成长期结论）
- **遗忘**：要不要有意识地忘？（隐私 / 减负）
- **格式**：jsonl（一行一条，可读）

### 3.5 边界
- 记忆**不写进人格** ✅（人格经内化住在 Agent 那里，不是程序里的文件）
- 记忆**不写进 stats.json**（那是数值）

## 4. 情绪系统

### 4.1 设计目标
桌宠有情绪，但**只表达社会情绪**，不表达基础情绪——因为基础情绪是「自我中心」的，而桌宠的存在意义是**面向主人**的。

### 4.2 情绪分类
| 类别 | 判据 | 桌宠是否表达 | 例子 |
|---|---|---|---|
| **基础情绪** | 不依赖自我/他人认知，纯生理反应 | ❌ **不表达** | 恐惧、愤怒、厌恶、快乐、悲伤、惊讶 |
| **自我意识情绪** | 需评估「我 vs 他人的标准」 | ✅ 可表达 | 羞耻、内疚、骄傲、尴尬 |
| **关系情绪** | 需评估「我 vs 你」 | ✅ **应表达** | 信任、感激、亲近、同情、依恋 |

### 4.3 用户情绪量尺
- **维度**：多向方位图 **mood（情绪）+ arousal（感知度）** 两轴，比单轴「开心/难过」信息量大。
- **衰减机制**：情绪标记随时间回落到 `neutral`，每30秒衰减5点，防止过时情绪长期残留。
- 数值判定：情绪倾向不明显时，数值应在50以下，反之，50以上。数值范围0-100。
- 防捉弄/戏耍：当LLM判断主人情绪反复横跳，阴晴不定时，如一会极度兴奋、一会极度难过，需考虑主人是不是在装，故意戏耍桌宠，桌宠要制定合理回应策略，如轻微愤怒：别一整天发神经了，我只是个电子宠物；放任：主人的情绪变化真有趣呢~；或其他。

### 4.4 桌宠自身情绪
- 来源：灵魂层（人格决定它「在意什么」）+ 数值系统（energy 等）
- 表现：映射到动画 + 语气 + 气泡（见 §7 映射表）

### 4.5 对话回应策略
- 输入：灵魂（人格）+ 用户情绪量尺 + 当前上下文（§5） + 记忆/画像
- 输出：本次**用什么情绪 + 说什么内容**
- 策略判断：策略分两种，一种是先定情绪和内容，再写正文。第二种是先写正文，再总结情绪和内容。从桌宠对话角度来说更好的角度是第二种，响应快速，不用等半天。

## 5. 环境感知

### 5.1 感知项
| 感知项 | 说明 | 感知方式 | 隐私|
|---|---|---|---|
| 天气 | 主人所在地天气 | 每4小时 | 低 |
| 宿主环境 | CPU/GPU/内存/硬盘占用 | 占用告急时 | 低 |
| 时间 | 日期时间 | 每轮 | 无 |
| 系统通知 | 最近的通知 | 计入事件池 | **高** |
| **前台窗口** | 主人正在用什么程序 | 主动开启 | **高** |
| **键鼠活跃度** | 空闲时长 → 判断在不在、忙不忙 | 分钟级 | 中 |
| **电源状态**| 插电/电池、电量 | 用电源且告急时 | 低 |

### 5.2 上下文组装
- **组成（现状）**：**不做注入**——程序把「数值 + 名字 + 画像 + 最近记忆 + 待处理事件 + 指令通道」组装成 `user://context.md`，由 Agent **自主读取**（不是拼进消息）；人格不在其中。
- **注意**：上下文对话历史由 Agent 自行管理，本地只做记录，不进入组装部分。退出桌宠或Agent不会清除对话历史。
- 提醒：Agent会话丢失或切换Agent，本地记录可以追回历史，不过这个功能暂时空置，有很多冲突待解决。
- **组装时机**：每次与 Agent 交互前

### 5.3 隐私与权限
- 通知 + 前台窗口是**次敏感数据**：要让桌宠懂主人，了解一些隐私是有必要的。
- 建议：**默认只存精简数据**（用完即弃），关闭开关在设置里。

## 11. 未来进化方向（策划提案，2026-09-22）

> 本节是**方向提案、暂不排期**——程序主体（动画系统重构等）打磨完成前，不进 `Plan表.md`；届时再按优先级分批落表。
> 判断尺子：① 服务设计目标（独立人格 / 感知环境 / 主动关心）；② 守住红线（不打扰、不油腻、不做注入、程序与交付分离）；③ 性价比（复用现有机制）；④ 强化独特性（人格住在 Agent 里、克制的集成、关心的是主人）。

### 11.1 生命感 —— 从「待命」到「在过日子」
> 像一个「在过自己日子的邻居」，而不是等待唤醒的响应器。

- **共感陪伴**：「不打扰」≠「不理你」——感知链（mood + 键鼠活跃 + 全屏 + 时间）判断主人在忙 / 闲 / 深夜 / 放松 → **用对的方式陪**：忙时安静趴着，深夜不劝睡、只是陪着。「存在即陪伴」。
- **情绪连续性**：mood 是主人的读数；它自己的情绪（§4.4）跨会话延续——「它还记着昨天的事」。
- **身体存在感**：贴边 / 爬边已有；多显示器移动、声音（TTS / KWS）——让它在桌面上「有实体」。
- **切口**：行为自然化重构（进行中）+ `DailyRoutine` 扩展。

### 11.2 关系纵深 —— 让陪伴「有时间」
> 功能会过时，「一起经历的时间」是独一份的资产。

- **相遇日**：记下首次运行时间戳 → 「我们认识第 N 天」。首启判定已有（`Main.cs:48`），只差一个时间戳——**极小改动、极高仪式感**。
- **破壳动画（与相遇日结合）**：**首次启动 = 破壳**——它从蛋壳里出来（裂壳 → 探头 → 站起 → 打招呼），这一刻即「相遇」；**相遇日 = 破壳日**，纪念日（周年 / 第 N 天）时可「重温」破壳作彩蛋。与首启引导（欢迎气泡）连成完整的「第一次见面」。切口：首启时播一段特殊动画序列；素材待定（VPet 有无破壳段待盘点，或用「程序化蛋壳 + 现有 rise 段」拼）。
- **桌宠日记**：Agent 定期从记忆里提炼「**它的视角**」写成日记 → 落盘成可读文件——「自我认知」的机制化，也是给主人翻的。切口：指令通道加一个落盘指令，程序侧近零成本。
- **记忆的温度**：记忆条目带情感标记 → 回忆时挑温暖的提起（「还记得那次…吗」）。
- **节日与仪式**：节日 / 纪念日的特别问候与庆祝、早安晚安、季节感（`DailyRoutine` 的时间段问候是现成底子）。
- **切口**：数据层小改 + Agent 侧任务，性价比极高。

### 11.3 具身 Agent —— 「Agent 有了身体」的前沿
- **从「假装思考」到「真的在思考」**：Agent 的真实状态流（收到活 → 思考 → 回复）映射到身体——它「认真起来」是可见的。
- **双向表达**：Agent 能读身体（`pet_context`）；反向让它「演」出心境——身体成为 Agent 的情绪出口。
- 这条线做出来，「桌面 Agent 人格化」的参考实现就立住了——业界少见。
- **切口**：ACP 状态 → 状态机的细化映射（think 已有一层）。

### 11.4 角色与交付 —— 「人格属于用户」
- **角色包标准**：动画池 + 话语表 + 人格材料 + 配置 = 一个可替换的**角色单位**（mods 机制已是雏形，缺规范文档）。
- **换机、换 Agent 不丢魂**：人格材料通用 + 数据可迁移（导出 / 导入）。
- 远期：角色生态——宁缺毋滥，先立标准。

### 11.5 信任与透明 —— 感知进化的前提
- **「它知道什么」可见**：知情清单——它知道主人的哪些事、存在哪。
- **可控可忘**：遗忘权——哪些事让它忘掉。
- **记忆所有权**：本地优先，数据是主人的。
- **切口**：配置窗「数据」页扩展（入口已有）。

### 11.6 外延想象（远期）
- **与创作线协同**：桌宠形象 ↔ 漫剧角色——角色 IP 双向孵化。
- **跨设备**（手机伴侣？）——谨慎，别摊薄「桌面」的独特性。
- **「AIPet 模式」白皮书**：人格内化 + 不做注入 + Agent 驱动——这套组合在业界是少数派，值得成文。
