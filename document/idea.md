## 0. 总纲：这个桌宠到底是什么

**一句话**：一个**有独立人格、能感知环境、主动关心主人**的桌宠，其大脑由本地 Agent（Hermes/Ollama）驱动，身体由 Godot 呈现。

**设计红线**：
1. **不打扰** —— 全屏/开会/专注时闭嘴；主动行为有频率预算。频繁打扰是桌宠三宗罪之首。
2. **不油腻** —— 卖萌有分寸；肉麻一次是萌，天天是负担。

**架构分层**（与 AGENTS.md 一致）：
```
灵魂层(人格) ──► 能力层(Agent脑) ──► 身体层(状态机) ──► 表现(动画/语音/气泡)
     ▲                  ▲
  记忆/画像          环境感知
```

## 1. 灵魂层 ——「灵魂」是什么

### 1.1 设计目标
灵魂 = **锚定人格的文件资产**，让桌宠的思考方式、说话方式**跨会话保持一致、不漂移**。

### 1.2 关键认知（技术前提，务必先读）
⚠️ **LLM 不会「读文件学习」，也不会被文件改变权重。** 人格的实现方式是：

```
灵魂文件 ──每轮对话注入──► 系统提示词(prompt) ──► LLM 当场按它演
```

所以灵魂文件的本质 = **人格提示词 + 思维范式示例（few-shot）**，是一份 **prompt 资产**，不是「专属大模型的编码」。

**让它不漂移的工程手段**：

| 手段 | 作用 |
|---|---|
| 每轮注入同一份灵魂文件 | 保证基线一致 |
| **思维范式示例**：「遇到 X → 我会这样想 → 这样说」 | 锚定人格：给模型看范式 |

### 1.3 灵魂「不该是什么」
- ❌ **不是数值记录表**（数值归独立的可视化 JSON，见 §2）
- ❌ **不是记忆存储**（记忆/画像归独立文件，见 §3）
- ❌ **不是模型的一部分**（是 prompt 资产）

### 1.4 灵魂「应该是什么」—— 人格模型建议
模仿人脑，把人格拆成**可泛化的思维模型**，每条都是「触发范式 → 反应范式」的示例对：

**A. 人格核心（Who am I）**
- 身份、来历、自我认知
- 性格坐标（随对话节奏而定）
- 说话风格范式（口头禅、语气、禁忌词）
- 价值观与原则（什么绝对不做、什么一定坚持）

**B. 思维范式（How I think）** ← 这是「不漂移」的核心
按事件类型建模，每类给 2-3 个**思维链示例**：
```
【事件类型：主人分享成就】
思维链：看到成就 → 先推上下文（不是敷衍夸） → 关心过程辛不辛苦 → 若有隐患温柔提醒
示例输出：「哇！这个你磨了好久吧，总算成了～不过那里可以完善下哦」
```
建议覆盖的事件类型（⚠️ 可增删）：
- 主人分享成就 / 主人受挫 / 主人提问 / 主人闲聊 / 主人很久没来 / 主人深夜还在工作 / 主人发脾气 / 主人说错话（默认纠正）/ 主人问及自己不擅长的事（默认主人不会）

**C. 关系定位（Who are you to me）**
- 桌宠与主人的关系称呼、边界感
- 亲疏表达方式

**D. 情绪表现规则**

    基础情绪（依赖自我认知）：恐惧、愤怒、厌恶、快乐、悲伤、惊讶 → 不该有
    自我意识情绪（需要评估「我 vs 他人/我的标准」）：羞耻、内疚、骄傲、嫉妒、尴尬 → 可以有
    关系情绪（需要「你」这个对象）：信任、感激、依恋、同情、亲近 → 应该有

### 1.5 文件格式
Markdown**（`.md`）—— 适合阅读修改，放人格段落与示例。

## 2. 数值系统

### 2.1 设计目标
数值是**状态表示**，不是成长属性。

### 2.2 沿用格式
- 格式：**JSON**（沿用原方案，机器读写为主）
- 位置：`user://state/stats.json`

### 2.3 基础字段（可由mod新增）

`mood` 情绪：由LLM判断用户情绪，属stats.json文件。
（暂时就这一个，想到再补充）

> 精力、亲密度、饱食度、等级等属于mod扩展范围

### 2.4 可视化呈现
- 面板形式：暂无，由mod实现

### 2.5 边界
- 数值**易变**，每帧/每分钟更新 → **不写进 soul.md**（否则文件频繁重写，人类阅读价值归零）
- 数值**不是人格**：改数值不该改变桌宠的说话方式

## 3. 记忆与画像

### 3.1 设计目标
记忆和用户画像**独立于灵魂**，因为它们的**生命周期完全不同**：
- 灵魂：几乎不变（人格）
- 画像：缓慢演化（用户是谁）
- 记忆：持续累积（发生过什么）

### 3.2 文件拆分
| 文件 | 内容 | 更新频率 | 谁写 |
|---|---|---|---|
| `soul.md` | 人格 / 思维范式 | 极少 | 主人手改 |
| `profile.md` | **用户画像**：主人的喜好、习惯、长期目标、知识面、作息 | 缓慢 | Agent 提炼 |
| `memory.md` | **记忆流水**：事件、对话要点、承诺 | 持续 | Agent 追加 |
| `stats.json` | 数值状态 | 高频 | 程序 |

### 3.3 用户画像要点（供参考）
- **稳定事实**：称呼、时区、职业、偏好
- **长期目标**：主人想做什么（桌宠要记住并适时关心）
- **知识面**：主人懂什么、不懂什么（决定解释深浅）
- **习惯模式**：作息、工作节奏、情绪触发点（如「周一早上烦躁」）
- 隐私边界：画像敏感数据脱敏

### 3.4 记忆管理机制
- **写入**：Agent 判断「值得记」才写
- **检索**：按什么召回？（关键词 / 时间 / 语义向量？）
- **压缩**：超量后怎么提炼？（把流水蒸馏成长期结论）
- **遗忘**：要不要有意识地忘？（隐私 / 减负）
- **格式**：md（可读）

### 3.5 边界
- 记忆**不写进 soul.md** ✅（承你的判断，正确）
- 记忆**不写进 stats.json**（那是数值）

## 4. 情绪系统

### 4.1 设计目标
桌宠有情绪，但**只表达社会情绪**，不表达基础情绪——因为基础情绪是「自我中心」的，而桌宠的存在意义是**面向主人**的。

### 4.2 情绪分类
| 类别 | 判据 | 桌宠是否表达 | 例子 |
|---|---|---|---|
| **基础情绪** | 不依赖自我/他人认知，纯生理反应 | ❌ **不表达** | 恐惧、愤怒、厌恶、快乐、悲伤、惊讶 |
| **自我意识情绪** | 需评估「我 vs 他人的标准」 | ✅ 可表达 | 羞耻、内疚、骄傲、尴尬 |
| **关系情绪** | 需评估「我 vs 你」 | ✅ **应表达** | 信任、感激、亲近、同情、依恋 |

### 4.3 用户情绪量尺
- **维度**：多向方位图 **mood（情绪）+ arousal（感知度）** 两轴，比单轴「开心/难过」信息量大。
- **衰减机制**：情绪标记随时间回落到 `neutral`，每30秒衰减5点，防止过时情绪长期残留。
- 数值判定：情绪倾向不明显时，数值应在50以下，反之，50以上。数值范围0-100。
- 防捉弄/戏耍：当LLM判断主人情绪反复横跳，阴晴不定时，如一会极度兴奋、一会极度难过，需考虑主人是不是在装，故意戏耍桌宠，桌宠要制定合理回应策略，如轻微愤怒：别一整天发神经了，我只是个电子宠物；放任：主人的情绪变化真有趣呢~；或其他。

### 4.4 桌宠自身情绪
- 来源：灵魂层（人格决定它「在意什么」）+ 数值系统（energy 等）
- 表现：映射到动画 + 语气 + 气泡（见 §7 映射表）

### 4.5 对话回应策略
- 输入：灵魂（人格）+ 用户情绪量尺 + 当前上下文（§5） + 记忆/画像
- 输出：本次**用什么情绪 + 说什么内容**
- 策略判断：策略分两种，一种是先定情绪和内容，再写正文。第二种是先写正文，再总结情绪和内容。从桌宠对话角度来说更好的角度是第二种，响应快速，不用等半天。

## 5. 环境感知

### 5.1 感知项
| 感知项 | 说明 | 感知方式 | 隐私|
|---|---|---|---|
| 天气 | 主人所在地天气 | 每4小时 | 低 |
| 宿主环境 | CPU/GPU/内存/硬盘占用 | 占用告急时 | 低 |
| 时间 | 日期时间 | 每轮 | 无 |
| 系统通知 | 最近的通知 | 计入事件池 | **高** |
| **前台窗口** | 主人正在用什么程序 | 主动开启 | **高** |
| **键鼠活跃度** | 空闲时长 → 判断在不在、忙不忙 | 分钟级 | 中 |
| **电源状态**| 插电/电池、电量 | 用电源且告急时 | 低 |

### 5.2 上下文组装
- **组成**：灵魂 + 本次输入 + 当前环境 + 用户画像摘要 + 相关记忆
- **注意**：上下文对话历史由 Agent 自行管理，本地只做记录，不进入组装部分。退出桌宠或Agent不会清除对话历史。
- 提醒：Agent会话丢失或切换Agent，本地记录可以追回历史，不过这个功能暂时空置，有很多冲突待解决。
- **组装时机**：每次与 Agent 交互前

### 5.3 隐私与权限
- 通知 + 前台窗口是**次敏感数据**：要让桌宠懂主人，了解一些隐私是有必要的。
- 建议：**默认只存精简数据**（用完即弃），关闭开关在设置里。

## 6. 互动方式

### 6.1 现有
| 交互 | 行为 |
|---|---|
| 左键 | 互动摸摸 |
| 左键双击 | 空置，由mod扩展 |
| 右键 | 弹出对话框，发指令 |
| 右键双击 | 弹窗确认进游戏模式，操控模式（WSAD + 空格跳跃） |
| 拖拽 | 移动位置 |
| 拖拽其上（文件/文件夹） | 交给桌宠处理 |

### 6.2 点击延迟
- 双击延迟遵循系统默认设置。
- **游戏退出方式**：游戏模式默认全屏无边框，右上角「点击 X 退出」，或右击界面 ➡ 菜单 ➡ 退出

### 6.3 补充交互（建议）
| 交互 | 建议行为 |
|---|---|
| **全局热键** | 随时唤出/隐藏桌宠（办公时不占地方） |
| **滚轮** | 默认缩放行为 |
| **悬停** | 长时间悬停有反应（好奇地看着你） |
| **语音** | **Kws（Sherpa-onnx）**——说话触发指令 |
| **多显示器** | 移动屏幕 |
| **贴边吸附** | 拖到屏幕边缘自动吸附 |

### 6.4 右键桌宠
- 唤出功能界面，有对话框，可与agent聊天,对话框下方是快捷命令菜单（工具箱、配置、游戏模式、退出等。）

## 7. 行为系统

### 7.1 主动行为
| 要点 | 说明 |
|---|---|
| **职责** | 了解主人的心情、状态、长期目标、知识面（原稿） |
| **情绪** | 只表达社会情绪（见 §4） |
| **不打扰约束** | 全屏/会议/专注时**静默**；主动频率预算（如每15分钟≤2次）；可关闭 |
| **主动行为清单** | 默认只执行职责，可添加：提醒喝水，提醒休息，分享发现，关心情绪。 |

### 7.2 被动行为（触发器）
| 触发器 | 反应 |
|---|---|
| 完成任务 | 庆祝（已有 `celerate` 动画） |
| 节假日 | 欢庆 |
| 用户长时间工作 | 劝休息（依赖 §5 键鼠活跃度感知） |
| **定时/日程**（补充） | 到点提醒 |
| **系统事件**（补充） | 电量低、网络断、下载完成 |
| **主人回来/离开**（补充） | 打招呼/告别 |

「打扰配额」可被主人调节

## 8. 信息池

### 8.1 三类表
1. 本地桌宠要用的信息（事件池、数值表、信息感知与查询）
2. Agent 上下文组装（灵魂、回应策略、记忆等）
3. 后台程序日志（错误/崩溃）

### 8.2 格式
| 记录 | 建议格式 | 理由 |
|---|---|---|
| 桌面行为/对话历史 | **jsonl** | 好做记录 |
| 后台日志 | **txt/log** | 标准日志 |

### 8.3 保留策略
- 单文件 10MB

### 8.4 隐私 ️
- 日志不含密码/敏感信息 → **脱敏**或**删除**

### 8.5 可回溯
- Agent 制定回应策略要给出依据（便于调试人格）

## 9. 能力

### 9.1 双路能力
| 路径 | 适用 | 例子 |
|---|---|---|
| **外部工具链（快速）** | 确定性/高频/本地 | 网速监控、截图、搜文件、下视频 |
| **Agent（人味、决策）** | 理解/决策/生成 | 聊天、判断情绪、规划 |

### 9.2 桌面小组件
- 网速监控 ✅
- 可扩展：CPU/内存/温度、待办、日历、音乐控制……

### 9.3 ️ 补充项
| 缺失 | 说明 |
|---|---|
| **TTS 语音输出** | Sherpa-onnx 已到位，桌宠**可以说话和聆听** |

| **用户画像** | 上限5k字符 |
