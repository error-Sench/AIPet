# 游戏模式动画需求清单（2026-09-22）

> **用途**：游戏模式新增/补齐动画的**素材需求单**——可直接派给 Agent / 画师执行。
> **原则**：**能导入 VPet 原版素材的优先导入**（同角色、零画工、风格 100% 一致）；VPet 没有的才新画，且必须**在现有帧基础上改**（同一角色，不许从零生成新角色）。
> 相关：导入管线 `tools/anim/import_vpet_anim.py`；池登记 `script/UX/CharAnim.cs`；玩法与键位 `script/Game/README.md`。

## 一、风格参考（硬性）

**角色 = VPet 官方模型「萝莉斯」**——现有素材全是她本人，新动作也必须是同一角色、同一画风。

| 参考物 | 位置 |
|---|---|
| **对齐基线帧**（导入器 REF，脚线/比例基准） | `mods/main_anim/anim/loris/idle/happy-1/000.png` |
| 风格样本（27 个池，随便开几张看） | `mods/main_anim/anim/loris/` |
| **原素材来源**（VPet 官方资产，与现有素材同源） | `D:/SteamLibrary/steamapps/common/VPet/mod/0000_core/pet/vup`（单角色 petname#萝莉斯） |

规格（导入器自动处理，**画的时候按这个来**）：

| 项 | 值 |
|---|---|
| 画布 | 512×512（导入器统一缩放） |
| 角色高 | ≈485px（= VPet 原版 948px × **固定缩放** 485/948；禁止按包围盒反推——躺/蹲姿势会被放大） |
| 帧名 | `%03d` 三位零填充、从 `000.png` 起（**字符串序**！别用 1、2、10） |
| 元数据 | `info.json`：`rate`（基准帧率）+ `durations`（逐帧相对时长 = ms÷基准，缺省全 1）——定格/慢动作靠它 |
| 目录 | `mods/main_anim/anim/loris/<池>/<变体>/`；动画名 = `<池>-<变体>`（如 `walk/left` → `walk-left`） |
| 左右成对 | 变体名 `left` / `right`（如 `attack/left`、`attack/right`） |
| 三段结构 | 变体名加 `-a`（入场）/ 主名（循环）/ `-c`（出场）；**一次性动作可只做单段** |
| 脚线 | 与 REF 帧对齐（导入器按角色包围盒对齐到现有基线） |

## 四、导入管线与硬规则（`tools/anim/import_vpet_anim.py` 头注释原文）

```bash
python tools/anim/import_vpet_anim.py            # 导入 SPEC 里全部池
python tools/anim/import_vpet_anim.py attack     # 只导某池（先在 SPEC 加条目）
```

1. 帧名重编号为三位零填充从 `000` 起（字符串序）
2. 缩放到 512×512 并按**角色包围盒**对齐到现有 loris 素材基线
3. 整段动画**只算一次**偏移逐帧套用——否则会抹掉帧间位移（动作本身）
4. 单目录多序列必须拆开：一个叶子目录里出现多于一个文件名前缀就跳过并告警（如 `1毛笔开心_*` + `2…退出通用_*`、`FLA_*` + `FLB_*`）
5. 丢弃 1bit/灰度遮罩层（`*_lay` / `front` / `back` 这类不是帧序列）——**注意**：`Eat/Drink/Gift` 的 `front_lay`/`back_lay` 是真双层，属例外
6. `info.json` 写 `rate` + `durations`（每帧相对时长；缺字段时加载端全按 1 处理，向后兼容）
7. **帧切片**：`(源, 起帧序号, 止帧序号)`（含端点，None = 全段），一个变体可由多片段拼接（实测 `SideHide_Right_Main/Nomal/A` 多粘了 2 帧开头 + 3 帧收尾）

**新画素材的注意事项**：

- 同一角色（萝莉斯）、同风格（Q 版 / 粗描边 / 平涂）、同比例（别整体放大缩小）
- 新帧要能自然衔接现有 `idle` / `walk`（脚线一致、朝向一致）
- 若用 AI 生成/重绘：**以现有帧为底图改动作**，不要重新生成角色（会串脸/串画风）
- 画完先自检：帧名三位、单序列单前缀、尺寸 512、脚线对齐——再跑导入器
