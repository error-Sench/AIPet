## 2. 灵魂层 —— 人格内化（程序不保存）+ 动态数据文件


```·
桌宠：只把**动态数据**写在磁盘上（不推送、不注入）
                  │
                  ▼   被读取（不是被推送）
Agent：按 skill 指引**自己来读**数据文件 ──► 当场按它演
（人格不在这里 —— 它已经在 Agent 自己身上：内化过一次，不是每轮读文件）
```

**硬规则 A（主人三次强调，2026-09-16 定稿）**：**我们不做主动注入**——不把数据拼进发给 Agent 的文本，
不写 `pre_llm_call` 之类的钩子，也不改 Agent 的 system prompt。交付物只有两个：**人格内化材料**（结构 + 示例，`dist/AIPet-SOUL.md`）+ **skill**
（用户把它提交给自己的 Agent）；Agent 按 skill 指引**自主读取**我们的数据文件。

**硬规则 B（主人四次强调，2026-09-20 定稿）：人格是「内化」，不是程序里的文件。**
`soul.md` 不是运行时读物——它是给 Agent 的**一次性内化材料**：Agent 读一次，把「桌宠是谁 + 职责与行动」写进**它自己的人设**（自主注入），之后不再重读；
运行时 Agent 只需要**会随时变动的数据**。程序侧**不保存人格、不供读人格文件**（`SoulTable` 已删除）；显示名是配置值（`config/config.json` 的「名字」，缺省「萝莉丝」）。

| 文件（skill 要写明的就是这些） | 路径 | 谁写 |
|---|---|---|
| 数值（主人情绪读数） | `user://state/stats.json` | 程序高频写（值由 Agent 经 set_mood 写入） |
| 名字（显示名） | `config/config.json`（配置目录，非数据目录） | 配置值（用户手编；缺省「萝莉丝」） |
| 画像（P4） | `user://soul/profile.md` | Agent |
| 记忆（P4） | `user://soul/memory.jsonl` | Agent |
| **上下文接口** | `user://context.md` | **程序自动生成**（**只此两处**：启动 + 事件池变动时——数值漂移不触发）|
| 指令协议（Agent → 桌宠） | `script/Agent/README.md` 的「指令通道」：**MCP 工具 `pet_command`**（首选，有回执）/ 回复文本内嵌 ` ```pet ` 围栏块（兼容） | 我们 |

### 上下文接口（`user://context.md`）—— 「Agent 不必到处翻文件」

主人定调（接口思想）：**上下文组装照做，但形态是「组装成一份文件让 Agent 来读」**，不是我们推送。
`ContextTable.组装()` 把「数值摘要 + 名字 + 画像 + 最近 12 条记忆 + 待处理事件 + 指令通道说明 + 各动态文件路径」拼成一份 md，
写到 `user://context.md`；**只在两处刷新**：启动时 + 事件池变动时（数值漂移/存盘刻意不触发——它不产生任何无谓 I/O）；要绝对最新可走 MCP 工具 `pet_context`（随包 `dist/aipet-mcp/`，调用即读盘）。文件头写明**只读**（下次生成覆盖）与**每个源文件归谁写**
（数值/名字 → 程序；画像/记忆 → Agent 自己写）。**不含人格**——人格在 Agent 自己的内化里。

实现：`script/Soul/ContextTable.cs`；探针：`tests/ContextProbe.cs`（17 断言：组装内容 / 脚手架只建不覆盖 / 只读不推送）。

所以人格的本质是 **prompt 资产**（提示词 + 思维范式示例），**不是**数值表、不是记忆库——它的载体是 **Agent 自己的人设**（内化后），而不是程序里的任何文件。

### 2.1 文件分离（关键决策）

| 文件 | 内容 | 更新频率 | 谁写 | 格式 |
|---|---|---|---|---|
| `config/config.json` | **名字**：显示名（聊天窗标题 / 说话人标签） | 静态 | 用户手编（配置目录） | json |
| `user://soul/profile.md` | **用户画像**：喜好、习惯、长期目标、知识面、作息 | 缓慢 | Agent 提炼 | md |
| `user://soul/memory.jsonl` | **记忆流水**：事件 / 对话要点 / 承诺 | 持续 | Agent 追加 | jsonl |
| `user://state/stats.json` | **主人情绪读数**：`mood`（0–100，中性 50；LLM 判断 → set_mood 写入；程序只做衰减与存储） | 高频 | 程序 | json |

**规则**：人格**不落程序**（内化进 Agent）；程序只存**动态数据**：数值归 `state/stats.json`；记忆/画像归独立文件（生命周期不同）。名字是**配置**（`config/config.json`），不是数据。**互不混写**。

**可视化（P5，入口在命令栏）**：命令栏「状态」按钮 → `script/UX/StatsWindow.cs`（独立窗口）。
**mood 用文字状态显示，界面上不出现任何数字**（超开心 / 心情不错 / 平平静静 / 有点蔫 / 不太开心 / 很低落）；
另留占位行（关系 / 记忆，尚未接入）。**数值层与界面解耦**：想看数字去 `user://state/stats.json`。

### 2.2 思维范式（「不漂移」的核心）
按事件类型给**思维链示例**，模型照着演：
```
【事件：主人分享成就】
思维链：看到成就 → 真诚高兴（不敷衍） → 关心过程辛不辛苦 → 若有隐患温柔提醒
示例：「哇！这个你磨了好久吧，总算成了～不过别熬太晚哦」
```
覆盖类型（可增删）：分享成就 / 受挫 / 提问 / 闲聊 / 很久没来 / 深夜工作 / 发脾气 / 说错话（纠正）/ 不擅长的事。

### 2.3 人格内化材料（`dist/AIPet-SOUL.md`）的结构

```markdown
---
version: 3
name: 萝莉丝
---

# 我是谁
（身份、来历、自我认知）

# 性格
（性格坐标 + 说话风格 + 口头禅 + 禁忌）

# 原则
（绝对不做 / 一定坚持）

# 思维范式
（按事件类型的思维链示例，见 §2.2）

# 情绪表达
（只表达社会情绪：信任/感激/羞耻/内疚/骄傲/同情/亲近；不表达基础情绪：恐惧/愤怒/厌恶/快乐/悲伤/惊讶。详见 §4 情绪规则。）
```

**原则**：内化材料结构变更 = `version+1` 并在本文档登记；材料本身可手改（它是给 Agent 读的内化素材，不是运行时文件）。

**边界**：游戏进度不入人格（归 `game/save.json`）；数值不入人格（归 `state/stats.json`）。

**P3 交付约束（硬规则，主人明确要求）**：
1. **不做主动注入**：不拼进消息、不写插件钩子、不碰 Agent 的 system prompt，也**不注入本机 Agent**。
2. 交付物 = **人格内化材料**（结构 + 示例）+ **skill**（用户提交给自己的 Agent）→ Agent 读一次、**把职责与人格写进自己的人设**（自主注入）；运行时只读**动态数据**：`state/stats.json` / `soul/profile.md` / `soul/memory.jsonl` / `events.jsonl` / `context.md`。
3. 两者**在项目完工时才写**（前期写不准）。
4. 本机只作开发/验证环境；验证「Agent 是否读得到」时用**独立 profile 的临时副本**，事后清理。

## 3. 本地话语表（`config/phrases.json` + `PhraseTable.cs`）

**它是什么**：桌宠*自己*说的小句子（不走 Agent 的那种）——**没接 Agent 时也有话可说**，桌宠不至于哑。

| 分类 | 什么时候说 |
|---|---|
| `问候`（分时段：早上/中午/下午/晚上/深夜） | **每次启动打一次招呼**（`DailyRoutine.启动问候()`；不占每小时预算） |
| `被摸` | 本地模式（没接 Agent）被点一下；**15s 冷却**防连点刷屏 |
| `捏脸` | 长按脸触发捏脸动作时（本地模式；5s 冷却） |
| `久坐` | 连续活跃到 `久坐提醒分钟` → 提醒站起来 |
| `磁盘` | 系统盘/程序盘余量低于阈值 → 每天一次的提醒（`{盘}` `{余量}` 占位符） |
| `降级` | Agent 配了却连不上时的那句人话 |

**行为约定**：随机抽一条且**不会连着重复**；分类留空数组 = 该类不说话；表缺失/坏掉 → **内置兜底**（与旧硬编码文案同款，永远不会哑）。
**分工**：接上 Agent 后，日常对话由 Agent 负责；这张表只负责「程序自己该说话」的场合。
**探针**：`tests/PhraseProbe`（解析/占位符/不连重/坏数据兜底/时段联动，21 断言）。
