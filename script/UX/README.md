## 面板群铁律（新建/改面板前必读）

| 铁律 | 原因（全部实测） |
|---|---|
| **UI 一律代码构建** | `.tscn` 里中文属性名会**静默失效**（见坑 #1） |
| **每个面板恰好一个自绘 ×** | `Borderless = true` 没有系统标题栏，否则关不掉（见坑 #5） |
| **`embed_subwindows=false` 才有真独立窗口** | 否则是被困在主窗口里的嵌入子窗口，标题栏点击无效（见坑 #5） |
| **弹窗不要设顶** | `AlwaysOnTop` 与 `PopupCentered()` 强制出的 transient 冲突，Windows 直接报错（见坑 #5） |
| **摆位必须做** | 漏了窗口就落屏幕 `(0,0)`（实测：状态窗「跑到屏幕左上角」）→ 统一用 `PanelPlacement.摆在桌宠旁(window)`；**探针也必须断言位置** |
| **接管指针名单要加全** | `WindowDrag.面板接管指针()` 必须包含每个面板，否则在面板上点/拖会误拖桌宠 |
| **重建子节点：先 `RemoveChild` 再 `QueueFree`** | 否则新旧节点叠加（见坑 #2） |
| **跨线程一律 `CallDeferred`** | 后台线程碰节点会报「can only be accessed from main thread」（见坑 #3） |

样式统一走 `MicaTheme`（云母浅色磨砂）；新面板**照抄现有面板的范式**最省事。

## 配置窗（`SettingsWindow.cs` + `Util/ConfigEdit.cs`）

**四个选项卡**：常规（语言 + 目录）／行为（状态机与主动行为全部开关 + 提示文字）／语音（TTS 开关与音色）／高级（Agent 后端、激进模式、桌宠缩放）。

| 项 | 做法 |
|---|---|
| 写入 | `ConfigEdit.写`：读 JSON → **只改目标键** → 写回（缩进 2、预留 `_comment` 与未知键、**中文不转义**）。写入位置沿用读取顺序（`ConfigFile.候选`：已存在的那个文件优先） |
| 生效 | 行为 → `StateMachine.设置.加载()`；语音 → `Tts.载入配置()`（都**立即生效**）；缩放 / Agent 后端 → 气泡提示「需重启生效」 |
| 控件 | 开关＝`Button(ToggleMode)` + `MicaTheme.应用开关`（开＝强调底色，关＝普通底）；数字＝`LineEdit`（回车/失焦提交、越界夹取、未变不写盘）；下拉＝`OptionButton` + 深色箭头 |
| 尺寸 | **固定尺寸（缺省 500×375，高:宽 = 3:4）+ 内容滚动**；调大小改 `config/panel.json` 的 `配置窗宽` / `配置窗高`（**不用重新编译**）。**不要改回自适应高度**（见下） |
| 回归锁 | `PanelProbe` 断言：4 个选项卡 / 滚动容器存在 / **行为页 7 个键** / 语音页 6 个键（键在构建时登记）+ **反向断言**：没必要的开关（贴边微调等）不许再塞回行为页（主人 2026-09-19）；`ConfigEditProbe` 断言写回三约定；`SettingsProbe`（非 headless）逐页截图 |

**尺寸三连坑（都实测过，别再踩）**：

1. 曾把高度写死 224px 且**没有滚动** → 后续加了「数据目录」行后底部被裁（主人看到「配置界面只有一截」）；
2. 改成「按内容自适应」后：**`TabContainer` 的最小尺寸只统计「当前可见页」** → 切到行为页时窗口没跟着变高、照样被裁；
3. 于是改成直接量页签容器 → 又碰到**「切页瞬间量到垃圾值」**（实测 3671px，下一帧才是真值）。

→ **结论（主人决定）：做固定尺寸 + 滚动窗口，不要自适应高度。** 调大小写 `config/panel.json` 的
`配置窗宽` / `配置窗高`（缺省 500×375）。
**改了数字没反应先查两处**：① 日志里那行 `[SettingsWindow] 固定尺寸: (宽, 高)` 有没有跟着变
（没变 = 改动没编译进去：编辑器 ▶ 会自动编，构建失败时 Godot 会继续跑旧 DLL）；② `PopupCentered()`
**不要用无参版本** —— 它按「内容最小尺寸」弹出，会盖掉固定尺寸；要显式传尺寸。

**另一个实测坑（截图类工具通用）**：`TabContainer` 换页在**下一帧**才生效——切页与截图**必须隔一帧**，同帧截图会拍到上一页。

## 动画池机制（`CharAnim.cs`）

- **`CharAnim` 是动画的唯一交汇点**：状态机（`script/State/`）只下发状态/动画名，不直接碰 `AnimatedSprite2D`。
- **新增池必须改 2 处**：`内置动画组`（否则不预载、播放失败）+ `OnAnimationFinished` 里的池判断（否则播完冻结在末帧）。
- **循环池**在 `循环动画组`（`walk` / `sleep`）：走动 6 帧 0.75s 而一次位移约 1s；睡觉是持续态，循环比「播完重播」更顺滑。
- `PlayNamed(动画名)` 精确播单段（走动的左右方向用它）；`PlayState(池)` 池内随机取一项（语义池用它）。
- 状态机与动画的**唯一交汇点**在 `OnAnimationFinished`：持续态让位给状态机重播，退出动画必须放行（见坑 #14）。

## 踩坑（本层）

### 踩坑 #1

1. **`.tscn` 里不能用中文属性名**。`关闭按钮 = NodePath("...")` 这类中文属性 Godot **不认且静默失败**，`[Export]` 绑定出来的引用是 `null`，表现为「按钮点了没反应」。→ 规则：**UI 一律代码构建**（`new Button{...}` + 手工 `AddChild`），不用 `[Export]` + 场景属性绑定。已按此范式：`ChatBox` / `ToolBar` / `SettingsWindow`。
---

### 踩坑 #2

2. **`QueueFree()` 是延迟释放**。重建子节点列表时若只 `QueueFree()` 不 `RemoveChild()`，旧节点仍在树中，会与新节点叠加（表现为「按钮重复成两份」）。→ 规则：重建前先 `RemoveChild(c)` 再 `c.QueueFree()`。
---

### 踩坑 #3

3. **跨线程不能碰 UI / 节点**。Agent 回调、子进程读取线程都在后台线程，直接访问节点会报 `get_translation_domain()/set_visible() can only be accessed from main thread`。→ 规则：后台线程只改数据，一律 `CallDeferred(nameof(方法), 参数)` 回主线程再碰节点（`CharAnim.PlayState` 已内置该保护）。
---

### 踩坑 #5

5. **无边框窗口没有系统标题栏**。`Window.Borderless = true` 时**不存在**系统的最小化/关闭按钮（已用整屏截图实证），窗口会关不掉。→ 规则：**关闭按钮必须自绘 ×**（`ChatBox` / `ToolBar` / `SettingsWindow` 三处统一此范式）。
   - 附：`window/subwindows/embed_subwindows=false` 才会让子窗口变成**真正的独立 OS 窗口**（否则是被困在主窗口里的嵌入子窗口，标题栏点击无效）。
   - 附：`AlwaysOnTop` 与 transient 冲突 —— `PopupCentered()` 会强制 transient，Windows 下报 `Windows with the 'on top' can't become transient.`。**不要给弹出窗口设置顶**。
---

### 踩坑 #12

12. **「手指命中区」不要加位置类历史约束**。`WindowDrag.IsInValidZone()` 里曾有一条旧补丁：要求鼠标在屏幕**下 2/3**
    （`mousePos.Y >= screenHeight/3`）——那是「窗口远大于角色」时代的产物。窗口现在正好套住角色，精确的窗口矩形判定已足够；
    保留它会让**桌宠靠近屏幕上边缘时完全无法拖拽**（顺带也卡住滚轮缩放，而滚轮缩放本身已按主人决策**删除**：
    运行时缩放会破坏动画链——素材偏移与贴边比例都是按固定缩放导入对齐的），而右键（走 `Context._UnhandledInput`，不经过该判定）却正常，
    所以现象是「点得到但拖不动」。
    - 规则：命中判定只用**窗口矩形**；判定函数拆出「传入坐标」的重载（`在桌宠内(Vector2I)`）以便探针不依赖真实光标。
    - 附带实测：`DisplayServer.WarpMouse` 用的是**窗口相对坐标**（请求全局 960 → 实际落 960+窗口X）；探针要移光标需传 `目标全局 - 窗口位置`。

### 气泡（`Dialogue` → `BubbleWindow`，P8/P9）

| 项 | 做法 |
|---|---|
| 架构 | 气泡是**独立无边框透明窗口**（`BubbleWindow`，懒创建挂到 root）——**不在桌宠窗口里**。原先那块固定 512×128、字号 32 的 RichTextLabel 已从 `game.tscn` **删掉**（桌宠窗口只有角色那么大，文字稍长必然被裁）|
| 自适应 | 按**字体实测**定尺寸：`Font.GetMultilineStringSize` 量自然宽与折行高；短文本小气泡，长文本到 `最大宽度像素` 折行、向上长高。RichTextLabel 同帧仍按旧宽度算高度（气泡虚高）→ **隔一帧校正一遍** |
| 位置 | 头顶居中（`距头顶像素`），上方放不下**翻到脚下**，四边夹进屏幕可用区；显示期间**每帧跟随**（拖拽/走动/贴边都不丢）|
| 交互 | **鼠标穿透**（`MousePassthrough`）——点气泡 = 点到底下的东西，不抢焦点；点它不会被挡住 |
| 文本 | 一律**当纯文本**：`[` → `[lb]` 转义（同 `ChatBox` 约定）；Agent 回复里的方括号不会再破坏布局 |
| 说话动作 | 气泡一出现 → `StateMachine.冒泡说话()`（`say` 池）；**不锁定 = 可被打断**、只在闲下来时演（白名单 `idle`/`bubble_talk`）|
| 时长 | `config/bubble.json` 的 `气泡显示秒`（默认 4）——**配置窗「行为」页可调**（改完立即生效）；气泡时长与动画无关 |
| 打字机 | 逐字显示（`打字速度字每秒`，0 = 直接整段）；**每次先 Kill 上一条 tween**（老代码连发气泡时两条 tween 会同时改 `visible_characters`）|
| 外观 | `config/bubble.json`：字号 / 最大宽度 / 内边距 / 圆角 / 不透明度 / 深色底 / 波浪效果 / 距头顶 / 打字速度（改完重启生效）|
| 调用约定 | `显示临时标题(文本)` **只收文本**；三个对外入口最终都汇到 `单例显示标题`（主线程唯一出口，跨线程由 `CallDeferred` marshal）|

**验证**：`tests/BubbleProbe`（headless，26 断言：说话动作 + 可打断 + 忙态/流式不偷 + 寿命 + 尺寸自适应 + 字号 + 穿透 + 转义 + 自动收）；`tests/BubbleShot`（**非 headless**，实机渲染存 PNG + 位置数值断言，含「上方放不下自动翻下方」）。

### 捏脸输入手势（`WindowDrag` × `FacePinch`，P7）

一次「按住桌宠」有三种结局，判定卡在**按下**与**移动阈值**之间：

| 手势 | 判据 | 结果 |
|---|---|---|
| **按住不动 300ms** | 鼠标在**脸区**（`捏脸命中区`，窗口比例）→ `FacePinch.按下` | 捏脸：A 进入 → B 循环 → 松手 C（锁定态，三段由 `FacePinch` 自管）|
| **一按就跑**（移动 > 5px） | `FacePinch.取消()` 作废候选 → 走老拖拽 | 拖窗口；**松手也不会补一个「摸摸」**（`捏过` 标志）|
| **按下即松** | 没捏过、没拖过、`_isPreparing` 还是本次按压 | 摸摸 —— **P10 起分部位**：脸区 → `interact` 序列；身体区（`HitRegion`）→ `interact_body`，30% 概率改成 `turn`（转身躲一下）；都不中 → 摸头（老行为）|

- 面板接管指针（`面板接管指针()`）时先 `FacePinch.取消()` —— 在面板上长按不该捏脸。
- **松手分支只收「本窗口管理的那次按压」**：老代码无差别 `FacePinch.松手()`，会把别的来源（探针、贴边、后续手势）的捏脸一起收掉 —— 已修（`_isPreparing || _dragging` 才收）。

**验证**：`tests/PinchProbe`（26 断言）。

### 网速监测桌面气泡（`NetSpeedBubble.cs`）

主人指定形态：**桌面气泡**（不是面板窗）—— 无边框 + 半透明圆角胶囊，**一行**数字（↓/↑）。

| 项 | 做法 |
|---|---|
| 数据 | `NetworkInterface` 的 IPv4 收发字节差分；只统计「已启用 + 非回环 + 非隧道」网卡（避免 VPN/虚拟网卡拱数字）；**纯本地、不联网、不落盘历史** |
| 交互 | 左键拖挪位置（位置+开关状态存组件目录的 `state.json`，换分辨率会被夹回屏内）、右键关闭；开关入口＝**工具栏「网速监控」**（`mods/toolbar/netspeed`：点按开/关，按钮带「·开 / ·关」；删目录或加 `_` 前缀＝移除/禁用）|
| 启动恢复 | 上次开着（enabled=true）且工具栏入口仍在 → 自动显示；删/禁用 mod 即不再恢复 |
| 懒创建 | **不在 game.tscn 挂节点**，首次打开时代码创建（避免给新 .cs 生成 .cs.uid 的编辑器依赖，未打开时零开销）|
| 不打扰 | **刻意不计入「面板可见」闸门**（它是"看"的，不是交互面）——气泡开着不影响桌宠自主行为 |
| 位置 API 坑 | 气泡自己的位置要用 `Window.Position`；`DisplayServer.WindowGetPosition()` 读的是**当前窗口**（=桌宠），实测踩过（夹屏逻辑改用它会把气泡按桌宠位置乱挪）|

**验证**：`tests/NetSpeedProbe`（格式化/差分/文本与历史/位置+开关状态持久化）+ `tests/ToolBarProbe`（工具格、点击开/关、启动恢复、组件自包含与指令派发机制）；非 headless 可截桌面屏做视觉复核。
